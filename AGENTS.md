# ПРАВИЛА ПРОЕКТА INFINITY-VERSE ДЛЯ АГЕНТОВ (AGENTS.md)

1. **Контекст и приватные заметки:**
   Обязательно читай файлы в `.private/` (`актуальное.md`, `заметки не менять без разрешения.txt`).

2. **Окружение:**
   Проект работает в чистом Windows (PowerShell, Node.js, Git).

3. **GitHub токен и синхронизация (ПУШ):**
   - **Где лежит токен:** Токен GitHub Personal Access Token хранится в `C:\Users\dikan\projects\.env` (на уровень выше репозитория) и/или в `.private/wallets.env` (`GITHUB_TOKEN=ghp_...`).
   - **КРИТИЧЕСКИ ВАЖНО:** Никогда не запускай голый `git push origin main` напрямую в командной строке! Git Credential Manager попытается открыть интерактивное окно авторизации, которого нет в headless-сессии агента, и команда зависнет намертво.
   - **Как правильно пушить:** Всегда запускай пуш через готовый скрипт:
     ```powershell
     powershell -ExecutionPolicy Bypass -File scripts\push_all.ps1 "сообщение коммита"
     ```
     Этот скрипт отключает интерактивные промпты (`GIT_TERMINAL_PROMPT=0`, `GCM_INTERACTIVE=never`), автоматически считывает токен из `..\.env` или `.private\wallets.env` и отправляет изменения в оба репозитория (основной и `.private`) за 3 секунды.

4. **Смарт-контракты (contracts-evm):**
   - **Актуальный стек контрактов:** В корне `contracts-evm/` хранятся только действующие контракты:
     * `InfinityVerse_Main_Ga_1.sol` (главный ончейн-накопитель Ga-1).
     * `InfinityVerse_AAA.sol` (модуль перемещения и спавна).
     * `InfinityVerse_BBB.sol` (модуль логики).
     * `правила наследования.md`.
   - Все старые поколения (`Main_G_1`, `Main_G_2`, `Main_G_3`, `V_0_...`) переносятся строго в `contracts-evm/archive/`.
   - **Компиляция контрактов:** Сборка выполняется через:
     ```bash
     node scripts/compile.js InfinityVerse_Main_Ga_1 InfinityVerse_Main_Ga_1
     ```
   - **Оптимизатор:** По умолчанию настроен на абсолютный максимум `runs: 4294967295` для минимальной стоимости газа вызовов в течение жизни контракта. Если новый код превысит лимит EVM (24 576 байт), снижать `runs` ступенчато: `1000000 -> 100000 -> 10000 -> 200`.
